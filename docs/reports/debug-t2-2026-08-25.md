## Fix đề xuất

### (1) Harness — scripts/verify_hybrid_flip.py

- Thêm tool shell để soft `<cmd>` có đích mapping, ví dụ khai báo thêm
  `"name": "Bash"` (input_schema `{command:string}`) + executor `subprocess.run`
  bounded (pattern như `exec_run_python`, dòng 225–238). Một dòng đăng ký trong
  `TOOL_EXECUTORS` (dòng 241) + list tools ở `level_t2` (dòng 363).
  Lưu ý: `_shell_tool_name` chỉ nhận tên "Bash"/"bash" (toolcall.py:102–105).
- Không cần nonce/conversation-isolation: mỗi run đã tự nhiên cách ly.

### (2) Gateway (dispatch fix riêng)

- `gpt/utils/toolcall.py:1066` — cho phép prose quanh soft tag: khi protocol=soft,
  parse với `allow_prose=True` (web model hay nói chuyện đuôi; fail-closed giữ cho
  xml/json-fn). Call site cần sửa: `gpt/utils/assistantturn.py:35` và
  `gpt/utils/toolstream.py:87,110`.
- `gpt/utils/toolcall.py:529` — khi definitions không có shell tool, đừng map `<cmd>`
  sang "Bash" ảo rồi văng "Unknown tool"; hoặc (a) translate `<cmd>` thành virtual
  Write/bash theo tool surface thật, hoặc (b) raise lỗi cấu hình RÕ ngay lúc build
  prompt (runtime) rằng soft protocol yêu cầu shell tool ở client.
- `gpt/gateway/runtime.py:942` — chỉ nối `_SOFT_HANDSHAKE_TEXT` dạng `<cmd>` khi
  client có shell tool; nếu không, handshake dạy variant `<json>{"name":…}</json>`.
- `gpt/gateway/runtime.py:962` — `del reason, detail` làm mất hoàn toàn phân loại
  lỗi trong correction; nên log reason/detail vào trace (không đưa vào model-facing
  text) để debug kiểu này không phải đoán.
